# JAR 包、C++ 插件与 SDK 的商业授权

**不必先做成带界面的完整软件，组件、插件和 SDK 也可以接入授权后收费。**

雪松授权云已有客户在这类交付场景中完成接入。本文对多个客户的场景做匿名归纳，下面的规则示例用于说明接入思路，不代表某个客户的具体配置。

## 客户交付的是什么

有的团队交付 Java JAR 包，有的交付 C++ 插件，还有的将自己的技术能力封装成 SDK，供其他开发团队集成。

他们需要管理的不是一个独立软件界面，而是：组件可以在哪台设备上运行、可以用多久、哪些功能允许调用。

## 授权怎么接进去

1. **创建产品和授权码**：把自己的组件作为产品管理，设置使用期限、允许激活的设备数量，以及需要开放的功能。
2. **在组件内校验授权**：初始化时校验许可证，在核心功能调用前检查授权是否仍然有效。校验失败时返回明确的授权错误，不执行受保护功能。
3. **随组件交付授权**：由集成方完成授权码激活；设备不能联网时，可通过手工导入许可证完成授权。

功能配置、使用限制和自定义参数需要由组件读取并执行，不是填写到后台后就会自动限制业务。

## 可以怎样按授权交付

例如，一个算法插件可以设置为：**允许激活 1 台设备、使用 1 年、只开放基础算法模块**。需要更多模块或更长使用期限时，再调整授权。

这让同一套组件可以按期限、设备数量或功能版本提供不同的商业授权，而不必为了收费另做一个完整的软件界面。

这里的设备数量指允许激活的设备数，不等于接口调用次数或并发数；如需限制调用用量，需要在组件中实现对应的计量与限制逻辑。

## 从哪里开始

打开 [AI 接入指南](/developer/ai-quickstart.html)，让 AI 在你自己的 JAR 包、插件或 SDK 项目中加入授权校验。按是否联网选择主流程，需要控制功能和额度时，再追加“许可证配置控制业务”模板。

**授权保护应放在组件的核心功能入口，而不只是外层演示程序里。** 这样交付给别人集成时，授权规则才会随组件一起执行。
