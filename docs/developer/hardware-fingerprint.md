# 硬件指纹策略

硬件指纹用于把许可证绑定到具体设备，降低授权码被复制到其他机器使用的风险。指纹策略越严格，防滥用能力越强，但客户更换硬件后需要重新激活的概率也会提高。

## 设计原则

| 原则 | 说明 |
|------|------|
| 稳定优先 | 选择不容易随软件升级变化的设备信息 |
| 可解释 | 客服和交付人员能解释为什么设备需要重新激活 |
| 可恢复 | 客户换机、维修、系统重装时有明确处理流程 |
| 不收集敏感信息 | 避免采集与授权无关的个人数据 |

## 常见字段

| 字段 | 稳定性 | 说明 |
|------|--------|------|
| MAC 地址 | 中 | 常用字段，但虚拟网卡或网卡更换会影响结果 |
| 主机名 | 中 | 易读，便于排查，但用户可能修改 |
| CPU 信息 | 高 | 稳定性较好，但跨平台采集方式不同 |
| 内存信息 | 中 | 可作为辅助字段，硬件升级可能变化 |

## 推荐策略

### 普通桌面软件

建议使用：

```plaintext
MAC + Hostname
```

适合轻量绑定，换机和重装场景较容易解释。

### 工业或设备软件

建议使用：

```plaintext
MAC + CPU + Hostname
```

适合对设备绑定要求更高的行业软件。

### 高价值离线交付

建议使用：

```plaintext
MAC + CPU + Memory + Hostname
```

适合离线交付、设备固定、授权价值较高的场景。需要提前告知客户硬件变更可能触发重新授权。

## 客户端处理建议

1. 固定字段顺序，避免同一设备生成不同指纹。
2. 对原始字段做规范化处理，例如去空格、统一大小写。
3. 不把原始硬件详情全部暴露给业务日志。
4. 生成指纹失败时给出明确错误提示。
5. 指纹变化时引导客户走换机或解绑流程。

## 常见问题

| 问题 | 说明 |
|------|------|
| 更换网卡后无法使用 | 如果指纹依赖 MAC 地址，网卡变化会导致指纹变化 |
| 虚拟机克隆后授权异常 | 多台虚拟机可能出现相同或变化的设备信息 |
| 系统重装后重新激活 | 主机名或硬件识别结果可能变化 |
| 离线设备换机 | 通常需要重新生成离线授权 |
