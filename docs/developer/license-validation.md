# 本地许可证校验

客户端激活成功后，应优先依赖本地许可证完成启动校验。即使是在线或混合模式，也不建议把每次启动都设计成强实时联网鉴权。

## 客户端需要保存什么

首次激活成功后，至少保存：

| 内容 | 说明 |
|------|------|
| `license_file` | Base64 编码的许可证文件 |
| 产品公钥 | 从产品列表“获取公钥”取得，并在开发或构建阶段内置到客户端的 RSA 公钥 |

启用心跳时还需要保存：

| 内容 | 说明 |
|------|------|
| `license_key` | 心跳接口使用的许可证密钥 |
| `heartbeat_interval` | 建议心跳间隔 |

## 校验顺序

```mermaid
flowchart TD
    A[读取 license_file] --> B[读取内置产品公钥]
    B --> C[Base64 解码许可证]
    C --> D[解析 algorithm、data、signature]
    D --> E[使用内置产品公钥验证 signature]
    E --> F{验签通过}
    F -->|否| X[拒绝启动并提示授权文件无效]
    F -->|是| G[解析 data]
    G --> H[检查 status]
    H --> I[检查 start_date / end_date]
    I --> J[检查 hardware_fingerprint]
    J --> K[读取 feature_config / usage_limits]
    K --> L[放行业务功能]
```

## 关键校验项

| 校验项 | 处理建议 |
|--------|----------|
| 签名 | 必须先验签，再读取业务授权内容 |
| 状态 | 只有 `active` 才能放行；`revoked`、空值和未知状态必须阻断，过期由有效期字段判断 |
| 有效期 | 检查当前时间是否在授权期内 |
| 硬件指纹 | 当前设备指纹应与许可证中的指纹一致 |
| 功能配置 | 根据 `feature_config` 控制模块开关 |
| 使用限制 | 根据 `usage_limits` 控制数量、额度或频率 |
| 自定义参数 | 根据 `custom_parameters` 映射业务参数 |

## 公钥与许可证关系

同一产品新签发的许可证使用同一套产品密钥签名。开发者应先在产品列表点击“获取公钥”，然后把完整 PEM 公钥写入客户端代码或随程序交付的只读资源。它是客户端判断“这张许可证是否由指定产品签发”的固定信任根。

激活、试用和按指纹恢复接口仍可能返回 `public_key`，这是兼容字段。客户端无需比较、保存或使用它，直接使用内置产品公钥验签即可。

- 同一产品的许可证使用该产品公钥验签。
- 客户端只需使用当前产品内置的公钥验签。

## 常见失败

| 现象 | 可能原因 |
|------|----------|
| 签名验证失败 | 许可证不是由内置产品公钥对应的私钥签发、许可证损坏、验签前重新序列化了 `data` |
| 授权已过期 | 本地时间超过许可证 `end_date` |
| 设备不匹配 | 当前硬件指纹和许可证绑定指纹不一致 |
| 功能不可用 | `feature_config` 未包含该功能，或使用额度已达上限 |
