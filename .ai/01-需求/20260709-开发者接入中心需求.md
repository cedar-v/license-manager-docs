# 开发者接入中心需求

## 背景与目标

License Manager 当前文档站已经提供快速开始、操作指南、SDK 索引、API 入口、许可证结构说明和客户端授权测试工具等内容，但这些内容分散在不同页面，读者需要自行判断接入顺序。

对于采购或试用 License Manager 的客户，真正影响转化和交付效率的是：客户工程师能否快速理解授权模型，并在自己的软件中完成首次激活、本地校验、离线授权、异常排查和上线检查。

本需求目标是在现有文档站基础上建设“开发者接入中心”，把分散资料重组为任务型接入路径，让开发者可以从一个入口完成接入学习、示例选择、排障定位和上线准备。

## 目标用户

| 用户角色 | 主要诉求 |
|----------|----------|
| 客户端开发工程师 | 快速在业务软件中接入授权激活和本地校验 |
| 后端开发工程师 | 理解授权接口、激活流程、心跳校验和错误处理 |
| 测试工程师 | 验证正常激活、过期、锁定、设备变更、离线授权等场景 |
| 技术负责人 | 判断接入成本、上线风险和生产环境检查项 |
| 售前/交付人员 | 用标准路径指导客户完成试用和接入验证 |

## 功能范围

### In Scope

1. 新增开发者接入中心入口
   - 在文档站中提供独立的“开发者中心”入口。
   - 首页按接入任务组织内容，而不是按资料类型罗列。
   - 支持开发者从首页进入快速接入、在线激活、离线激活、SDK、API、错误排查和上线检查。

2. 提供三类接入方式
   - 选项 1：AI 快速接入，面向希望让 AI 辅助完成项目改造的用户。
   - 选项 2：SDK 标准接入，面向希望少处理底层接口、验签和心跳细节的用户。
   - 选项 3：原生 API 灵活对接，面向暂无 SDK 语言、已有授权框架或需要完全自定义客户端逻辑的用户。
   - 明确三种方式的适用场景、推荐程度和后续阅读路径。

3. 拆分在线激活和离线激活文档
   - 在线激活文档说明有网络环境下的接入流程、输入输出、客户端保存内容和常见失败原因。
   - 离线激活文档说明无网络环境下的请求文件、授权文件、导入校验和使用限制。
   - 两类场景的读者路径要独立，避免混淆。

4. 建立 SDK 接入专区
   - 按语言组织 SDK 接入文档。
   - 第一阶段以 C# SDK 作为标杆接入文档。
   - 后续覆盖 C++、Go、Python 和 HTTP API 等入口。
   - 每个 SDK 页面应说明适用场景、安装方式、最小接入流程、关键配置、许可证校验、常见错误和相关链接。
   - C# SDK 页面作为其他语言 SDK 文档的结构模板，优先打磨完整。

5. 建立接口与错误排查专区
   - API 文档不只链接 Swagger，还要按开发者任务解释关键接口。
   - 错误排查文档按症状组织，覆盖授权码不存在、已过期、被锁定、激活次数已满、设备指纹不一致、签名验证失败、许可证文件损坏、客户端时间异常、网络不可达、API Key 无效等问题。
   - 每个问题提供确认方法和处理建议。

6. 提供生产上线检查清单
   - 在客户正式上线前，提供自检项。
   - 覆盖授权策略、测试授权、生产授权、许可证保存、错误提示、离线兜底、日志记录、版本发布和客户支持准备。

7. 关联现有资料
   - 复用现有许可证结构、客户端模拟器、SDK 索引、Swagger 入口和操作指南。
   - 对已有页面进行必要链接调整，避免重复维护同一内容。

### Out Scope

1. 本阶段不开发 SaaS 后台里的动态接入工作台。
2. 本阶段不实现在线调试台、应用创建向导、API Key 生成、沙箱环境管理等后台功能。
3. 本阶段不修改 License Manager 服务端接口行为。
4. 本阶段不修改 SDK 代码。
5. 本阶段不承诺一次性完成所有英文文档，可先完成中文主路径，再规划英文同步。
6. 本阶段不替代 Swagger，Swagger 仍作为完整接口列表入口。

## 功能点与验收标准

### 1. 开发者中心首页

**功能点**

- 提供“从哪里开始”的接入导航。
- 按任务展示：快速接入、在线激活、离线激活、SDK 接入、API 接口、错误排查、上线检查。
- 明确推荐路径：首次接入优先阅读快速接入，再按接入模式进入具体文档。

**验收标准**

- 用户从文档首页或导航栏能进入开发者中心。
- 用户在开发者中心首页能在 10 秒内找到首次接入入口。
- 首页能区分在线激活、离线激活和 SDK 接入，不把所有内容混在一个列表中。

### 2. 三类接入方式

**功能点**

- 开发者中心首页直接展示“选项 1 / 选项 2 / 选项 3”。
- AI 快速接入页说明用户需要把哪些文档链接和项目代码提供给 AI。
- SDK 标准接入页说明 SDK 是推荐路径。
- 原生 API 灵活对接页承载接口级接入流程。

**验收标准**

- 新用户能在开发者中心首页清楚选择三种接入方式之一。
- AI 快速接入页能告诉用户应提供哪些链接给 AI。
- 原生 API 灵活对接页能覆盖准备测试授权、执行激活、校验许可证、处理失败。
- 文档不把部署 License Manager 与接入客户软件混为一谈。

### 3. 在线激活文档

**功能点**

- 说明在线激活适用场景。
- 描述客户端首次激活、保存许可证、后续启动校验的流程。
- 说明网络异常、授权码异常、设备异常时的处理方式。

**验收标准**

- 读者能区分首次在线激活和后续本地校验。
- 文档明确在线激活成功后客户端需要保存哪些授权相关信息。
- 文档包含常见失败场景的跳转链接。

### 4. 离线激活文档

**功能点**

- 说明离线激活适用场景。
- 描述离线请求、联网签发、离线导入和本地校验的业务流程。
- 说明离线授权的限制和操作注意事项。

**验收标准**

- 读者能理解离线环境下为什么需要请求文件和授权文件。
- 文档能指导交付人员向客户解释离线授权流程。
- 文档包含离线授权常见问题入口。

### 5. SDK 接入专区

**功能点**

- 提供 SDK 总览页。
- 按语言提供接入入口。
- 每个 SDK 页面突出最小业务启动流程，而不是展示过多演示功能。

**验收标准**

- 用户能从 SDK 总览页选择目标语言。
- C# SDK 页面达到可作为其他语言模板复用的完整度。
- SDK 文档能说明业务系统应该读取哪些授权信息来控制功能开关、使用额度或自定义参数。

### 6. API 与错误排查

**功能点**

- 提供面向开发者任务的 API 说明入口。
- 提供错误码和排障说明。
- 排障内容按问题现象组织。

**验收标准**

- 用户遇到激活失败时，可以通过排障页定位可能原因。
- 每个常见问题至少包含现象、可能原因、确认方法和解决建议。
- API 页面能引导用户跳转到完整 Swagger。

### 7. 生产上线检查清单

**功能点**

- 提供正式上线前的自检清单。
- 覆盖授权策略、测试覆盖、错误提示、日志、离线策略、客户支持资料等。

**验收标准**

- 技术负责人可用该清单评估接入是否具备上线条件。
- 检查项具备可操作性，不只写原则性描述。
- 检查清单能链接到相关接入文档。

## 内容组织建议

第一阶段建议形成以下文档树：

```text
docs/developer/
  index.md
  quickstart.md
  activation-online.md
  activation-offline.md
  license-validation.md
  hardware-fingerprint.md
  sdk/
    index.md
    csharp.md
    cpp.md
    go.md
    python.md
    http-api.md
  api/
    index.md
    activation.md
    heartbeat.md
    errors.md
  troubleshooting.md
  production-checklist.md
```

该结构是需求建议，不代表必须一次性全部实现。第一阶段最小可交付可以只包含首页、快速接入、在线激活、离线激活、C# SDK、排障和上线检查。

## 优先级

| 优先级 | 内容 | 原因 |
|--------|------|------|
| P0 | 开发者中心首页、AI 快速接入、SDK 标准接入、原生 API 灵活对接、在线激活、C# SDK、错误排查 | 直接影响客户首次接入成功率 |
| P1 | 离线激活、许可证校验、硬件指纹、上线检查 | 影响真实交付和生产上线 |
| P2 | C++ SDK、Go SDK、Python SDK、HTTP API 专区、英文同步 | 扩展覆盖范围和国际化体验 |
| P3 | 与 SaaS 后台动态接入工作台联动 | 后续产品化增强 |

## 非功能需求

1. 文档结构清晰，开发者从入口到完成接入不应跳转过多。
2. 文档语言保持工程化和可操作，不写营销口号。
3. 代码示例应短小，优先体现真实业务启动流程。
4. 不暴露真实密钥、私钥、客户信息或生产授权码。
5. 文档中涉及接口和 SDK 行为时，必须与当前实际实现保持一致。
6. 新增文档需要能被站内搜索检索。
7. 新增中文主路径后，应为英文同步预留结构。

## 已确认决策

1. 开发者中心作为文档站一级导航展示，导航名称使用“开发者中心”。
2. 第一阶段只做中文文档，英文文档延后规划。
3. 第一阶段以 C# SDK 作为标杆 SDK 文档，其他语言后续补齐。
4. 文档中的示例授权码、接口地址、应用标识使用统一的雪松授权云平台占位值，默认平台地址为 `https://lic.cedar-v.com/`。
5. 第一阶段需要同步调整首页入口，以及现有 `guide/sdk.md`、`guide/api.md` 与开发者中心的跳转关系。
6. 客户端模拟器暂不定位为开发者中心导航中的“调试工具”，第一阶段不纳入开发者中心导航。
