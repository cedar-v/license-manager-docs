# 项目开发规范

## 分层规范

本仓库以 VitePress 文档为主，开发工作分为三类：

| 类型 | 说明 |
|------|------|
| 内容文档 | Markdown 页面，主要位于 `docs/guide/`、`docs/en/guide/`、`docs/policies/` |
| 站点配置 | VitePress 配置，主要是 `docs/.vitepress/config.mjs` |
| 静态资源 | 图片、CSS、站点清单等，位于 `docs/public/` |

新增接入类文档优先放在独立目录，避免继续堆叠到现有指南目录导致入口混乱。中文和英文需要长期保持结构对应，但可以按阶段先完成中文主路径。

## 命名约定

- `.ai` 文档日期统一使用 `YYYYMMDD`。
- 需求文档路径使用 `.ai/01-需求/{YYYYMMDD}-{需求简称}需求.md`。
- 设计文档路径使用 `.ai/02-设计/{YYYYMMDD}-{需求简称}设计.md`。
- 交付文档路径使用 `.ai/03-交付/{YYYYMMDD}-{需求简称}交付.md`。
- 文档页面文件名使用英文小写和连字符，例如 `quickstart.md`、`activation-online.md`。
- 中文页面标题使用清晰业务名称，例如 `# 10 分钟接入 License Manager`。

## 错误处理

- 文档中涉及错误码、接口失败、SDK 异常时，应按“现象、可能原因、如何确认、解决方法、相关文档”的结构描述。
- 不应只给结论，应告诉读者如何自查。
- 对暂未确认的接口行为，不写成确定事实，应标记为待确认。

## 接口规范

- 文档中引用接口时，应说明使用场景、请求前置条件、关键请求字段、关键响应字段和常见错误。
- 面向开发者的 API 说明应优先按任务组织，例如在线激活、离线激活、心跳校验，而不是只按后端路由罗列。
- 保持与实际 Swagger、SDK README 和服务端行为一致。

## 日志规范

- 文档站本身不产生业务日志。
- 排障文档中涉及日志时，应说明读者应该查看哪类日志或页面，例如客户端日志、服务端接口响应、授权记录、设备记录、调试台结果。
- 不暴露敏感信息示例，例如完整 API Key、真实私钥、客户手机号或生产授权码。
