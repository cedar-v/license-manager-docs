# AI 原生接口快速接入设计

日期：2026-07-23

## 设计目标

让用户在需要加入授权功能的软件项目根目录中启动 AI 编程工具，再粘贴固定协议提示词与一个可修改的业务模板，即可完成雪松授权云原生 API 接入，不依赖 SDK，也不要求用户手工复制项目代码。

开发者中心在概览下方提供独立的业务接入方式指导，帮助用户先选择授权流程，再进入带“推荐”标志的 AI 原生 API 快速接入页面复制提示词。

## 核心决策

1. **协议优先**：`/api/v1` 接口、许可证格式、验签算法和状态边界是唯一事实源。
2. **两段式上下文**：固定协议与可变业务分开；用户复制协议后，再选择一个业务模板。
3. **原生 API 一等支持**：AI 按项目语言和现有架构实现；SDK 仅作为可选便利层。
4. **协议层不包含业务假设**：只定义接口、许可证、算法、错误码和不可违反的安全边界。
5. **业务模板可扩展**：首批提供最小在线激活、在线试用、心跳远程管控和纯离线导入四种主模板，以及许可证配置控制业务的可叠加模板。
6. **可验证**：每个业务模板包含与该场景匹配的验收测试。

## 两段式结构

```text
固定协议提示词
  ├─ HTTP 输入输出
  ├─ 许可证结构
  ├─ RSA-PSS 验签
  ├─ 状态与错误码
  └─ 安全不变量

可选业务提示词
  ├─ A 最小在线激活
  ├─ B 在线激活 + 试用
  ├─ C 心跳与远程管控
  ├─ D 纯离线手工导入
  └─ E 配置驱动业务（叠加到 A–D）
```

最终上下文为：`以对接项目根目录为 AI 工作目录 + 固定协议 + 一个经过用户修改的主模板 + 可选附加模板`。

## 本次纠正的关键协议事实

- 当前真实许可证 `data.status` 的有效值是 `active`，撤销值是 `revoked`。
- `normal / locked / expired` 属于授权码状态，不应作为当前许可证状态枚举。
- RSA-PSS-SHA256 的 salt length 等于 SHA-256 哈希长度，即 32 字节。
- 签名原文是许可证顶层 `data` 的原始 UTF-8 字节，禁止重新序列化。
- 心跳 `usage_data` 是服务端保存的完整快照，不应按增量补丁理解。

## 与 SDK 的关系

最佳实践不是删除所有 SDK，而是：

```text
一份版本化协议规约
        ↓
原生 API + AI 自动接入
        ↓
可选薄 SDK / 示例 / 一致性测试
```

SDK 可以降低传统开发者的接入门槛，但不能承载独占协议知识。任何 SDK 都应服从同一规约并通过同一套一致性测试。
